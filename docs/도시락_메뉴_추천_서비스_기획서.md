## 0. 브랜드 — 모락 (Morak)

### 이름의 의미 (세 겹의 의미를 동시에 담음)

1. **"모으다 + 모두의 + 도시락"** — 냉장고에 있는 재료를 모아, 모두의 도시락을 만든다
2. **"도시락도 락(樂)이다"** — 도시'락'에서 따온 '락(樂)'. 매일의 도시락이 즐거움이 되는 서비스
3. **"김이 모락모락"** — 갓 만든 따뜻한 음식의 이미지. 정성과 따뜻함의 의성어

### 슬로건 후보

- **"모아 담아, 모락"** — 가장 직관적 (재료를 모아 도시락에 담는다)
- **"오늘도 모락모락"** — 일상의 정겨움
- **"도시락도 락(樂)이니까"** — 컨셉 잘 살림
- **"냉장고가 가벼워지는 시간"** — 기능적 가치 강조

> 추천: 메인 슬로건 **"모아 담아, 모락"**, 서브 카피로 **"오늘도 모락모락"** 같이 활용

### 마스코트 컨셉

- 동그란 주먹밥 친구가 **모자처럼 김(증기)을 모락모락 쓰고 있는** 캐릭터

## 1. 한 줄 소개

**모락(Morak) — "냉장고 속 재료의 유통기한을 기준으로, 오늘 만들 도시락 메뉴를 추천해주는 서비스"**

버리는 재료 없이, 다음 장보기까지 알차게 도시락을 싸고 싶은 사람을 위한 메뉴 큐레이션 도구.

---

## 2. 풀고 싶은 문제

- 냉장고에 뭐가 있는지 모르고 새로 사다 보면 재료가 상해서 버린다.
- "오늘 뭐 싸지?" 매일 결정하는 게 피곤하다.
- 레시피 앱은 많지만, **내 냉장고 상황**에 맞춰주는 곳은 드물다.
- 부족한 재료를 사야 하는데, 한 번 살 때 **여러 메뉴에 활용 가능한 것**을 사고 싶다.

---

## 3. 타겟 사용자

- 매일/자주 도시락을 싸는 20–40대 1–2인 가구
- 식비를 절약하고 싶지만 매번 메뉴 정하기 귀찮은 사람
- 냉장고 정리/식재료 낭비를 줄이고 싶은 사람

**핵심 페르소나**

| 항목 | 내용 |
|------|------|
| 이름 | 미정 (29, 직장인, 1인 가구) |
| 상황 | 점심 도시락을 싸지만 메뉴가 매번 똑같음. 주말에 산 재료가 자주 상함. |
| 니즈 | "오늘 뭐 싸지" 결정을 5분 안에 끝내고 싶음. 재료를 다 쓰고 싶음. |

## 4. 핵심 기능 (MVP 범위)

### 4.1 재료 등록

- 보유 중인 재료를 입력 (이름, 수량, 유통기한)
- 카테고리: 채소 / 육류·해산물 / 유제품·계란 / 양념 / 기타
- 기본은 **수동 입력** (검색하면 자주 쓰는 재료가 자동완성으로 뜸)

### 4.2 메뉴 추천 (메인 로직)

- 보유 재료로 만들 수 있는 도시락 메뉴 리스트를 보여줌
- **유통기한이 임박한 재료를 포함하는 메뉴를 상단 우선 노출**
- 각 메뉴 카드에 표시:
  - 메뉴 이름 / 대표 사진 / 예상 조리 시간
  - "내 재료로 100% 만들 수 있음" or "재료 2개 부족"
  - 임박 재료 뱃지 (예: "유통기한 D-1: 시금치 활용")

### 4.3 메뉴 선택 → 부족 재료 안내

- 메뉴를 선택하면 필요한 재료 vs 보유 재료를 비교
- 부족한 재료를 **장보기 리스트** 형태로 보여줌
- 장보기 리스트는 체크해서 "구매 완료" 처리 → 보유 재료에 자동 추가

### 4.4 연쇄 메뉴 추천

- 메뉴 선택 후, "이 재료들을 추가로 사면 만들 수 있는 또 다른 메뉴"를 함께 제안
- 예: "어묵 1팩 더 사면 → 어묵볶음도 가능"
- 한 번 장보기로 **2–3개 메뉴를 한 주에 돌릴 수 있게** 유도


## 6. 플랫폼 결정: **Expo (React Native + Web) — 앱·웹 브릿지 스택**

### 왜 Expo인가

진주의 요구 조건은 세 가지: ① 네이티브 앱으로 배포하고 싶다, ② 웹과 코드가 브릿지되어야 한다, ③ 수정이 있을 때 배포가 쉬워야 한다. 이 셋을 동시에 만족하는 가장 실용적인 스택이 Expo다.

- **하나의 React Native 코드베이스 → iOS · Android · Web 세 플랫폼 동시 빌드**
- **EAS Update (OTA 업데이트)** — 스토어 심사 없이 JS 코드 변경을 앱에 즉시 push. 스타일·문구·비즈니스 로직 수정은 앱 재제출 불필요
- **Expo Router** — Next.js와 유사한 파일 기반 라우팅. 웹 SEO에도 유리
- Supabase 등 백엔드는 그대로 재사용 (플랫폼 무관)

### 코드 공유 구조

```
apps/
  mobile/            iOS·Android 진입점 (Expo)
  web/               Web 진입점 (Expo Web / Next.js 감쌈)

packages/
  ui/                공용 컴포넌트 (재료 카드, 메뉴 카드, 마스코트 SVG...)
  logic/             추천 알고리즘, 유통기한 계산 등 순수 함수
  api/               Supabase 클라이언트, 타입, 훅
  design-tokens/     §9 컬러/타이포/블롭 형태 값 (단일 소스)
```

`packages/*`는 웹·모바일이 100% 공유하고, `apps/*`는 플랫폼별 진입점만 다름. 나중에 카메라·푸시 등 네이티브 전용 기능은 모바일 앱에서만 붙임.

### 배포·수정 흐름 (핵심)

| 수정 유형 | 배포 방법 | 걸리는 시간 |
|----------|-----------|-----------|
| JS/스타일/카피 수정 | `eas update --branch production` | **1~2분, 심사 X** |
| 새 화면·비즈니스 로직 추가 | `eas update` | **1~2분, 심사 X** |
| 네이티브 모듈 추가 (카메라 lib 등) | `eas build` → 스토어 재제출 | 심사 1~3일 |
| 웹 버전 배포 | Vercel `git push` | **자동, 즉시** |

핵심은 **네이티브 진입점을 바꾸지 않는 한 대부분의 업데이트가 심사 없이 즉시 반영**된다는 것. 사이드 프로젝트 특성상 빠른 반복 실험에 최적.

### 기술 스택 요약

- **프레임워크**: Expo SDK 51+ (React Native 0.74+), Expo Router
- **웹 진입점**: `expo export --platform web` → Vercel 호스팅
- **UI**: NativeWind (Tailwind for RN) — §9 디자인 토큰을 그대로 씀
- **백엔드**: Supabase (Postgres + Auth + Storage + Realtime)
- **상태 관리**: Zustand or Jotai (가볍고 웹/앱 공용)
- **폼**: React Hook Form + Zod
- **날짜(유통기한 D-day)**: date-fns
- **애니메이션**: Reanimated 3 (앱), Framer Motion (웹) — 마스코트 상태 전환용
- **배포**:
  - 앱: EAS Build → App Store / Play Store
  - 앱 업데이트: **EAS Update (OTA)**
  - 웹: Vercel (자동)
  - CI: GitHub Actions (푸시 → EAS Update / Vercel 자동 배포)

### 트레이드오프 (솔직히)

- **장점**: 코드 공유율 80%+, 심사 없는 즉시 배포, 웹 랜딩 겸용, 자산 재사용
- **단점**: React Native만의 어려움(디버깅·네이티브 이슈), 웹 스타일링이 NativeWind로 살짝 제약, PWA만큼 URL 공유가 자연스럽진 않음(앱 링크 필요)
- **완화**: 웹 진입점을 살려두면 URL 공유·SEO 문제 해소. 초창기엔 웹으로 지인 테스트, 반응 좋으면 앱 심사 진행

## 7. "사진/이미지 자동 스캔" 기능 검토

결론: **1차 배포에서는 제외**. 캡처화면·포장지 인식은 Phase 2로 미룸.

> 진주의 코멘트 반영: 영수증보다는 **장바구니 캡처화면 / 포장지 봉지 사진**을 자동 인식하는 시나리오를 염두에 두고 있음.

### 시나리오별 난이도 (재정리)

| 시나리오 | 난이도 | 비고 |
|---------|--------|------|
| **장바구니 캡처화면 인식** (쿠팡·마켓컬리 등 주문 내역) | **중하** | 이미지 OCR로 텍스트 추출 후 재료명·수량만 파싱하면 됨. 마트 영수증보다 포맷이 깔끔해서 오히려 쉬움. |
| **포장지·봉지 사진 인식** (제품명 + 유통기한) | **중** | 제품명은 OCR로 가능. 유통기한은 위치/표기가 제각각이라(YYYY.MM.DD / YY/MM/DD / 제조일+소비기한 등) 보정 필요. 사용자 확인 단계 필수. |
| 식재료 자체 이미지 인식 ("이거 양파야") | **상** | 학습된 모델 필요. 정확도 70–80% 수준이라 UX 망가지기 쉬움. |
| 냉장고 안 사진 한 장 → 전체 재료 추출 | **매우 상** | 현재 기술로도 불완전. 멀티모달 LLM(Claude/GPT-4o vision)으로 가능하나 비용·속도 이슈. |

### 단계별 도입 전략

1. **1차 배포 (MVP)**: 수동 입력 + 자동완성 (자주 쓰는 재료 사전 100개 시드)
2. **Phase 2**: 장바구니 캡처화면 OCR → 재료 자동 등록
3. **Phase 3**: 포장지 사진에서 제품명·유통기한 동시 인식
4. **Phase 4**: 영양성분 분석 (사용자가 언급한 향후 기능)
5. **Phase 5+**: 멀티모달 LLM으로 "냉장고 사진 한 번에 스캔" 실험

> **OCR 후보**: Naver CLOVA OCR, Google Cloud Vision, Apple Vision (iOS), Tesseract.js. 호출당 약 5–20원 수준이라 비용 부담은 낮음.

## 7-1. 1차 배포 범위 (확정)

**들어가는 것 (MVP / 1차 배포)**

- ✅ 재료 등록 (수동 입력 + 자동완성)
- ✅ 유통기한 관리 (등록 시 입력, 임박 알림 배지 + 로컬 푸시)
- ✅ 보유 재료 기반 메뉴 추천 (유통기한 임박 우선 정렬)
- ✅ 메뉴 선택 → 부족 재료 → 장보기 리스트
- ✅ 장보기 완료 → 보유 재료 자동 이동
- ✅ 연쇄 메뉴 추천 ("이거 더 사면 만들 수 있는 메뉴")
- ✅ **iOS / Android 앱** (Expo Build → App Store / Play Store)
- ✅ **웹 버전 동시 지원** (Expo Web → Vercel, 랜딩 페이지 겸용)
- ✅ **EAS Update로 심사 없이 즉시 배포** (JS/스타일/문구 수정)
- ✅ 시드 데이터: 메뉴 50개 + 재료 사전 100개

**1차 배포에서 빠지는 것 (의도적 보류)**

- ❌ 사진/이미지 자동 스캔 (캡처화면·포장지 OCR) → Phase 2
- ❌ 영양성분 분석 → Phase 4
- ❌ 공유 냉장고 (가족·룸메이트)
- ❌ 메뉴 평점·코멘트
- ❌ 마트별 가격 비교, 외부 쇼핑몰 연동
- ❌ 식단 캘린더 / 주간 식단표
- ❌ 회원가입·로그인 (1차에선 익명 로컬 저장 + Sync는 옵션)

## 8. 데이터 모델 (개략)

```
User
 └─ Ingredient (재료)
      ├─ name (시금치)
      ├─ category (채소)
      ├─ quantity (200g)
      ├─ expiryDate (2026-06-01)
      └─ addedAt

Menu (메뉴 마스터)
 ├─ name (시금치 무침)
 ├─ cookingTime (10분)
 ├─ tags (한식, 도시락, 채소)
 └─ RequiredIngredient[]
      ├─ name (시금치)
      ├─ quantity (100g)
      └─ optional (선택재료 여부)

ShoppingList
 └─ Item
      ├─ ingredientName
      ├─ quantity
      └─ purchased (boolean)
```

추천 알고리즘은 단순하게 시작:

1. 보유 재료로 **모든 필수 재료**가 충족되는 메뉴 = "바로 가능"
2. 1–2개 부족한 메뉴 = "조금만 사면 가능"
3. 임박 재료 활용 메뉴는 가중치 ↑ (예: D-1은 +30점)

## 9. 디자인 톤 가이드 (Quiet Warm — calette 스타일)

> **레퍼런스**: calette UX/UI (Behance) — 순백 베이스 위에 카테고리별 파스텔 그라데이션, 손으로 그린 듯한 둥근 블롭(organic shape), 색상별 마스코트, 큰 산세리프 한글 헤드라인 + 작은 영문 대문자 라벨, 모카 베이지 액션 컬러.

### 전체 무드

- **순백 베이스 + 카테고리별 파스텔 포인트** — 화면 상단에만 부드러운 그라데이션을 깔아 카테고리/맥락을 구분
- **풍부한 여백** — 카드를 빽빽이 채우지 않고 숨 쉴 공간을 충분히
- **손그림 톤의 블롭(organic shape)** — 사각/원형이 아닌, 살짝 비대칭의 부드러운 곡선으로 재료·메뉴 일러스트
- **단순하고 가벼운 그림자** — `0 2px 12px rgba(0,0,0,0.04)` 수준의 옅은 띄움 정도. 무거운 그림자 X
- **배경 데코** — 작은 삼각형·원·짧은 선들이 화면 모서리에 살짝 흩어진 정도

### 타이포그래피

- **헤드라인 (한글)** — Pretendard 700, 28~32px, line-height 1.4, letter-spacing -0.02em
  - 사용 예: "오늘 당신의 / 도시락은 ?", "냉장고에 / 어떤 친구들이 있나요"
  - calette처럼 **두 줄로 나눠** 큰 한글을 천천히 읽게 함
- **서브 헤드 (한글)** — Pretendard 400, 13~14px, color: 그레이 브라운
- **영문 대문자 라벨** — Pretendard 700 / Nunito 700, 11~12px, letter-spacing 0.12em, 대문자
  - 사용 예: "FRIDGE", "TODAY'S MENU", "SHOP LIST"
  - 카드/섹션 위에 작게 얹어 분위기를 만듦
- **본문** — Pretendard 400/500, 13~14px
- **숫자** — Nunito 700 (D-1, 조리시간 등 숫자에 활용해 가독성·리듬감 ↑)

> Gowun Dodum 같은 손글씨체는 **마스코트 말풍선 / 특별 카피**에만 제한적으로 사용 (전체 톤은 모던한 산세리프 유지).

### 일러스트 / 형태 언어

- **재료·메뉴 비주얼은 이모지 X → 블롭(organic shape) 일러스트** 사용
  - 단순한 둥근 곡선 + 카테고리 컬러 + 살짝 비대칭의 자연스러움
  - 시금치 = 초록 잎 블롭 한두 장 / 두부 = 부드러운 흰 직사각 블롭 / 계란 = 노란 타원 블롭
- **모서리 반경**: 카드 20px, 버튼 14px, 칩(태그) 999px(완전 원형)
- **선 굵기**: 외곽선 1px 또는 사용 안 함 (대부분 그림자만으로 분리)
- **배경 데코**: 화면 모서리에 작은 삼각형·원·짧은 선 (8~12px) 흩뿌리기. 너무 많이는 X

### 모락 마스코트 — 톤 조정

기존 김 모자 쓴 주먹밥 컨셉은 유지하되, calette 스타일에 맞춰:

- 외곽선 더 가늘게 (1.2~1.5px)
- 채도 낮춰 차분하게 (블러시 핑크 볼터치 정도)
- **상태별 표정 4종** 준비
  - `기본` — 윙크하며 살짝 미소
  - `임박 알림` — 살짝 다급, 모자(김) 더 크게 모락모락
  - `완료` — 양 손 들고 환호
  - `빈 화면` — 빈 도시락통 안고 멍하게

### 보이스 톤

calette의 차분하고 미니멀한 톤을 따라 — **꾸미는 말 줄이고, 명사형으로 끊고, 잔잔하게**.

| 상황 | OK (calette 톤) | 너무 아기자기해서 X |
|------|----------------|-----------------|
| 헤드 인사 | "오늘 / 어떤 도시락을 모아볼까요?" | "오늘도 모락모락 든든하게!!" |
| 임박 알림 | "유통기한이 임박한 친구가 있어요." | "어머나! D-1 친구가 3명이나!" |
| 완료 화면 | "모락에 새 친구들이 도착했어요." | "와아 도시락 완성!! 🎉" |
| 빈 상태 | "냉장고가 비어 있어요. 첫 친구를 추가해 주세요." | "재료를 모아주세요!! 모락모락!" |

- 존댓말 + 마침표
- 이모지·느낌표 매우 절제 (마스코트 일러스트가 감정을 표현)
- 키워드 '모락'·'모락모락'·'락(樂)'은 **카피 곳곳에 분산**, 한 문장에 한 번만

세 겹의 의미를 동시에 담는 작명:
1. **모으다 + 모두의 + 도시락** (재료를 모아 모두의 도시락으로)
